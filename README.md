# Инвест Обзор

Локальный веб-сервис для личного учёта инвестиций: портфели, активы, операции, дивиденды и аналитика. Самостоятельная реализация основных сценариев из [обзора Snowball Income](https://ru.help.snowball-income.com/overview/), без использования его серверного кода, аккаунтов или баз данных.

Все рабочие данные хранятся в SQLite. Интерфейс не использует CDN и аналитику. Ручной учёт работает без интернета; для загрузки данных Т-Инвестиций сервер обращается к официальному REST API банка. Библиотека `cryptography` используется для шифрования токена.

## Быстрый запуск без Docker

Нужен Python **3.12 или новее** с модулем `sqlite3`.

```bash
cd /home/alex/Projects/invest-obzor
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py
```

Откройте **http://localhost:8080**. Создайте свой портфель или нажмите «Открыть демо». Демо — отдельный портфель с условными ценами и историей; его можно удалить в настройках.

По умолчанию данные сохраняются в `data/invest.sqlite3`, а сервер слушает только `127.0.0.1`. Для другого порта или расположения базы:

```bash
.venv/bin/python server.py --port 8090 --db /путь/к/invest.sqlite3
```

Путь также можно задать переменной `INVEST_DB`. Остановка сервера: `Ctrl+C`. При следующем запуске данные сохранятся.

## Запуск через Docker Compose

Нужен Docker с Compose.

```bash
docker compose up -d --build
```

Откройте **http://localhost:8080**. Данные находятся в именованном томе `invest-data`, а ключ шифрования — в отдельном томе `invest-secrets`. Приложение в контейнере работает от непривилегированного пользователя. Docker устанавливает зависимости автоматически.

```bash
docker compose logs -f
docker compose down
```

`docker compose down` сохраняет данные и ключ. `docker compose down -v` удаляет оба тома.

Для обновления исходников пересоберите контейнер командой `docker compose up -d --build`.

### Развёртывание в доверенной локальной сети

По умолчанию опубликован только loopback-порт. Для сервера `192.168.0.100` и порта `8900` создайте файл `.env` рядом с `compose.yaml`:

```dotenv
INVEST_BIND_ADDRESS=192.168.0.100
INVEST_PORT=8900
INVEST_ALLOWED_HOSTS=192.168.0.100
```

Запустите `docker compose up -d --build`. Адрес: **http://192.168.0.100:8900**. `restart: unless-stopped` обеспечивает запуск контейнера после перезапуска Docker/сервера. Нужен включённый автозапуск самого Docker. Проверка: `docker compose ps`, `docker compose logs --tail 50`.

`INVEST_ALLOWED_HOSTS` — явный список адресов через запятую, без протокола и порта. Остальные Host-заголовки отклоняются, а Origin должен совпадать с адресом страницы. Это защита от подмены адреса и запросов с посторонних сайтов, **не** сетевая авторизация. Устройства с прямым доступом к порту могут читать и изменять данные. Не публикуйте его в интернет.

HTTP в LAN не шифрует передачу между браузером и сервером. Для ввода брокерского токена используйте SSH-туннель, который шифрует этот участок:

```bash
ssh -N -L 8900:192.168.0.100:8900 chat@192.168.0.100
```

Затем откройте **http://localhost:8900/#tbank**. Порт 8900 на вашем компьютере должен быть свободен. В файле `.env` находятся только сетевые настройки; брокерский токен вводится через интерфейс и туда не записывается.

## Что работает

- Несколько независимых портфелей с базовой валютой, целью по капиталу и плановым пополнением.
- Акции, облигации, фонды, криптовалюты, металлы и произвольные активы. Категории задаются при редактировании актива.
- Создание, редактирование и удаление операций: пополнение, вывод, покупка, продажа, дивиденды, купоны, отдельная комиссия.
- Комиссии, налоги с выплат, дробное количество активов, проверка остатка при продаже на дату операции.
- Денежные остатки по валютам; RUB, USD, EUR, CNY, GBP, HKD, CHF и KZT. Курсы к рублю задаются вручную, исторический курс можно указать в операции.
- Общая стоимость, прибыль, средняя стоимость покупки, результат продаж, рост открытых позиций и история выплат.
- Оценка годовых выплат из введённой суммы на единицу, распределение активов и сравнение с целевыми долями.
- История стоимости в виде ежедневных снимков. Новые снимки сохраняются при изменениях и открытии портфеля; внутридневной снимок обновляется.
- Импорт CSV с проверкой перед применением, экспорт операций и резервная копия всей базы.
- Адаптивный русский интерфейс, поиск активов и фильтры.
- Раздел «Т-Инвестиции»: подключение read-only токена, счета, текущие позиции и цены, денежные остатки и исполненные операции. Синхронизация по кнопке, с пагинацией и сохранением локальной копии.

## Подключение Т-Инвестиций

1. Создайте **отдельный токен «Только чтение»** в [настройках Т-Инвестиций](https://www.tbank.ru/invest/settings/api/). По возможности ограничьте доступ нужным счётом. Приложение проверяет `accessLevel` счетов и отклоняет токены с торговыми или неопределёнными правами.
2. В приложении откройте **Т-Инвестиции** в левом меню. Вставьте токен в поле пароля и нажмите «Проверить и сохранить». Не передавайте токен в чате, GitHub, URL или командной строке.
3. Выберите счёт, укажите начало периода операций и нажмите **Синхронизировать**. По умолчанию используется дата открытия счёта.
4. После завершения появятся стоимость счёта в RUB, изменение за день, позиции, денежные остатки, заблокированные суммы и история исполненных операций. Позиции и история сохраняются для просмотра без интернета.

Запросы выполняются сервером по HTTPS к фиксированному адресу `https://invest-public-api.tbank.ru/rest/`. Используются только `GetAccounts`, `GetPortfolio`, `GetPositions`, `GetOperationsByCursor`; торговые методы отсутствуют. Песочница в этой версии не подключена. Для запроса операций применяются UTC-даты, даже если интерфейс показывает время в часовом поясе браузера.

Брокерские счета показываются **отдельно от ручных портфелей**. Исходные операции и оценки брокера сохраняются без преобразования в ручной журнал сделок; текущие остатки не создают фиктивные покупки и пополнения. Средняя цена и результат позиции взяты у брокера и не являются расчётом общей прибыли за всю историю. Инструменты, НКД, переводы, комиссии и налоги остаются в исходных данных API. Денежный поток операции и её комиссия отображаются отдельно и повторно не складываются.

Синхронизация заменяет операции выбранного периода целиком: это учитывает удаление и смену ID операции на стороне брокера и предотвращает повторное начисление выплат. Более старые операции вне этого периода сохраняются. При сетевой ошибке, неправильной пагинации или смене токена во время запроса предыдущий снимок не изменяется. Выполняется максимум 100 страниц по 1000 операций; при превышении выберите меньший период. Интерфейс выдаёт историю страницами по 100 записей. Фонового опроса и потоковых котировок нет; для обновления нажмите кнопку снова. Портфель и остатки запрашиваются последовательно, поэтому не являются единым биржевым снимком на одну наносекунду.

Если новый токен открывает другой набор счетов, локальные копии недоступных ему счетов удаляются. Сохраните резервную копию перед сменой области доступа.

Документация банка: [токены](https://developer.tbank.ru/invest/intro/intro/token), [счета и уровни доступа](https://developer.tbank.ru/invest/services/accounts/users), [операции и портфель](https://developer.tbank.ru/invest/services/operations/methods), [REST endpoint](https://developer.tbank.ru/invest/intro/developer/protocols/).

## Хранение API-токена

- Токен хранится **только на сервере**, в таблице `broker_credentials`, в зашифрованном виде (Fernet: аутентифицированное шифрование из `cryptography`). Ключ и токен не записываются в Git, логи, HTML, cookies, `localStorage` или `sessionStorage`.
- Ключ автоматически создаётся при первом успешном подключении: `.secrets/master.key`, каталог `0700`, файл `0600`. Настройка `INVEST_MASTER_KEY_FILE` позволяет вынести его за пределы проекта, например в защищённый каталог пользователя. Содержимое ключа не передаётся через env, только путь к файлу. В Linux слишком открытые права на файл и символические ссылки отклоняются.
- В Docker ключ находится в `/secrets/master.key`, в отдельном томе `invest-secrets`. Исходники, образ и том с финансовой базой ключ не содержат. `.gitignore` и `.dockerignore` исключают `.secrets`, `.env`, приватные ключи, базы и экспорты.
- Токен передаётся браузером один раз локальному серверу в JSON-теле запроса; поле очищается. GET API возвращает только признак подключения и время сохранения. Сервер использует токен только в HTTPS-заголовке `Authorization` к фиксированному домену банка; переадресации и системные прокси отключены. Тексты ошибок банка не выводятся, чтобы исключить случайное отражение секрета.
- **Скачиваемая резервная копия не содержит токенов**, включая зашифрованные. После создания копии таблица с секретами очищается, затем выполняется `VACUUM`. При восстановлении подключите токен заново. Если делаете собственную файловую копию рабочей базы, она содержит шифротекст — храните ключ отдельно от такой копии.
- При утрате ключа существующий токен не перезаписывается новым ключом автоматически. Восстановите файл ключа либо удалите подключение и введите токен заново. После удаления подключения приложение может создать новый ключ при его отсутствии.
- Для замены токена вставьте новый в разделе «Т-Инвестиции». Старый токен отзовите в кабинете банка. «Удалить подключение» удаляет локальную запись, но не отзывает токен в банке; WAL-файлы и собственные старые копии БД могут сохранять старый шифротекст. Финансовая история при отключении остаётся доступной локально.

Шифрование защищает секрет при утечке одной базы данных. Оно не защищает от пользователя/root или вредоносного процесса, имеющего доступ одновременно к базе, ключу и памяти работающего сервера. Это приложение одного пользователя: по умолчанию сервер и Docker-порт остаются на loopback, сетевой авторизации и HTTPS для внешнего доступа нет. Развёртывание в доверенной LAN настраивается отдельно, как описано выше. Не публикуйте порт в интернет; для безопасной передачи токена используйте SSH-туннель. Не включайте логирование тел запросов в стороннем прокси.

Перенос ключа на обычном Linux-запуске: остановите приложение, переместите `.secrets/master.key` в защищённый каталог с правами `0700`, сохраните права `0600` и запустите сервер с `INVEST_MASTER_KEY_FILE=/путь/к/master.key`. Не создавайте новый ключ, если требуется сохранить текущий зашифрованный токен. Для плановой смены ключа проще удалить подключение, остановить сервер, убрать старый файл ключа, запустить сервер и сохранить заново выпущенный read-only токен; старый токен отозвать в банке.

## Первые шаги

1. Создайте портфель и выберите базовую валюту. После создания базовая валюта фиксируется.
2. Если используете другие валюты, в «Настройках» задайте их курсы к рублю. При базовой валюте, отличной от RUB, задайте также её курс. Примерные курсы автоматически не подставляются.
3. Внесите пополнение в валюте брокерского счёта.
4. В «Моих активах» добавьте актив: тикер, валюту, категорию и текущую цену.
5. Внесите покупку или импортируйте операции CSV. Количество и средняя цена рассчитываются из сделок.
6. По мере необходимости обновляйте цены, записывайте выплаты и сохраняйте резервные копии.

Количество облигаций — в штуках, цена и купон — в денежных единицах за одну облигацию. НКД, амортизация и проценты от номинала отдельно не моделируются. Если используете облигации, учитывайте это при подготовке операций.

## Расчёты

Денежные расчёты на сервере используют `Decimal`; в базе значения сохраняются строками, без перевода в двоичный `float`. Принимается до 12 знаков после запятой. Кросс-курс операции, рассчитанный из настроек, округляется до 12 знаков. Интерфейс округляет суммы только для отображения.

Операции обрабатываются по дате, затем по порядку создания внутри одного дня. Для продажи на конкретную дату должно хватать купленных к этой дате единиц. Изменение или удаление покупки, которое нарушило бы последующие продажи, отклоняется целиком.

| Показатель | Расчёт |
| --- | --- |
| Стоимость портфеля | Рыночная стоимость открытых позиций + денежные остатки |
| Чистые пополнения | Пополнения − выводы, по зафиксированным курсам операций |
| Общая прибыль | Стоимость портфеля − чистые пополнения |
| Себестоимость позиции | Средняя стоимость покупок с комиссией, за вычетом себестоимости проданного |
| Рост открытой позиции | Текущая стоимость − оставшаяся себестоимость в базовой валюте |
| Результат продажи | Выручка за вычетом комиссии − средняя себестоимость проданных единиц |
| Полученные выплаты | Дивиденды + купоны − налоги − комиссии выплат |
| Прогноз выплат | Текущее количество × введённая выплата на единицу в год, до налогов |
| Доля актива | Стоимость актива / стоимость всех открытых позиций, без денежного остатка |

Базовая себестоимость покупки использует её исторический курс. Денежные остатки и текущая стоимость активов пересчитываются по текущим курсам из настроек. Для старых операций задавайте `fx_rate` явно: приложение не загружает исторические курсы.

Денежный баланс может стать отрицательным: это позволяет загрузить неполную историю, но интерфейс показывает предупреждение. Автоматического обмена валют нет: обмен отражайте выводом одной валюты и пополнением другой, с курсами, при которых их суммы в базовой валюте совпадают.

График стоимости показывает сохранённые оценки, а не восстановленную биржевую историю. Если вы загрузили сделки за прошлые годы, котировки за эти годы автоматически не появятся. Старые снимки после исправления операций не пересчитываются. В демо-портфеле исторические точки синтетические и помечены как демонстрационные.

Доходность XIRR/TWR, бенчмарки, рейтинг дивидендов, фундаментальные мультипликаторы, автоматические котировки ручных портфелей, календарь объявленных будущих выплат и импорт собственных XLS/XML-форматов брокеров **не реализованы**. Прогноз выплат ручного портфеля — простое вычисление из ваших данных. Интеграция с Т-Инвестициями описана выше; другие брокеры не подключены. Приложение предназначено для одного пользователя; аккаунтов и сетевой авторизации нет. По умолчанию Compose публикует порт только на loopback; доверенная LAN требует явной настройки адреса и разрешённых хостов.

## CSV: импорт и экспорт

В интерфейсе: **Импорт CSV → Выбрать файл → Проверить файл → Импортировать**. До последнего шага база не меняется. При ошибке в строке или недостатке активов для продажи весь файл отклоняется. Повторный импорт точно того же файла в тот же портфель запрещён. После изменения файла его содержимое уже считается другим; частичное дублирование строк автоматически не определяется.

Поддерживается UTF-8, включая BOM, запятая или точка с запятой как разделитель, до 1 МБ и 5000 операций. Числа можно записывать с десятичной точкой; с десятичной запятой используйте разделитель `;` или CSV-кавычки.

[Готовый пример](static/example.csv):

```csv
date,type,ticker,name,kind,category,currency,quantity,price,amount,fee,tax,fx_rate,note
2025-01-10,deposit,,,,,RUB,,,100000,0,0,1,Первое пополнение
2025-01-15,buy,SBER,Сбербанк,stock,Финансы,RUB,100,250,,10,0,1,Пример покупки
2025-07-20,dividend,SBER,Сбербанк,stock,Финансы,RUB,,,3484,0,452.92,1,Пример выплаты
```

| Поле | Значение |
| --- | --- |
| `date` | Дата фактической операции `YYYY-MM-DD`, не позднее сегодня |
| `type` | `deposit`, `withdrawal`, `buy`, `sell`, `dividend`, `coupon`, `fee` |
| `ticker` | Нужен для покупок, продаж, дивидендов и купонов |
| `name`, `kind`, `category` | Для создания нового актива. `kind`: `stock`, `bond`, `fund`, `crypto`, `metal`, `other` |
| `currency` | Валюта операции; у существующего актива должна совпадать с его валютой |
| `quantity`, `price` | Положительные количество и цена за единицу для покупки/продажи |
| `amount` | Полная сумма до удержаний для остальных операций. В сделках считается как количество × цена |
| `fee` | Комиссия в валюте операции, отдельно от `amount` |
| `tax` | Налог, только для дивидендов и купонов |
| `fx_rate` | Единиц базовой валюты за одну единицу валюты операции; в базовой валюте — 1. Если пропущено, берётся текущий курс из настроек |
| `note` | Необязательный комментарий |

Новый тикер создаёт актив автоматически. Его начальной котировкой становится цена из первой строки; после импорта обновите её в редакторе актива. CSV переносит операции, а **не** текущие котировки, цели и всю историю оценки. Для полного переноса используйте резервную копию SQLite.

## Резервная копия и восстановление

В интерфейсе: **Настройки → Резервная копия**. Это согласованный снимок финансовых данных, сформированный SQLite Backup API; его можно скачать при работающем сервере. API-токены из скачиваемой копии исключаются; ключ шифрования также не включается. После восстановления заново подключите токен. Экспорт CSV рядом — только операции выбранного ручного портфеля. Если ручных портфелей нет, копию можно скачать по [http://localhost:8080/api/backup](http://localhost:8080/api/backup).

### Обычный запуск

1. Остановите сервер (`Ctrl+C`).
2. Сохраните старый каталог `data` отдельно.
3. Замените `data/invest.sqlite3` скачанной копией. Если остались `data/invest.sqlite3-wal` и `data/invest.sqlite3-shm`, уберите их из рабочего каталога вместе со старой базой. Нельзя смешивать новую базу со старыми WAL-файлами.
4. Запустите сервер снова. Если использовался `--db` или `INVEST_DB`, заменяйте именно тот файл, который указан при запуске.

### Docker Compose

Поместите копию в корень проекта под именем `backup.sqlite3`, затем:

```bash
docker compose stop
docker compose run --rm --no-deps -v "$PWD/backup.sqlite3:/restore.sqlite3:ro" invest-obzor python -c 'import sqlite3, shutil; from pathlib import Path; c=sqlite3.connect("file:/restore.sqlite3?mode=ro", uri=True); assert c.execute("PRAGMA integrity_check").fetchone()[0] == "ok"; assert c.execute("SELECT count(*) FROM portfolios").fetchone(); c.close(); shutil.copyfile("/restore.sqlite3", "/data/invest.sqlite3"); Path("/data/invest.sqlite3-wal").unlink(missing_ok=True); Path("/data/invest.sqlite3-shm").unlink(missing_ok=True)'
docker compose up -d
```

Перед восстановлением сохраните текущую резервную копию. Команда восстановления заменяет базу в томе. Она не должна выполняться одновременно с работающим приложением.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tests/smoke_http.py
node --check static/app.js
node --check static/broker.js
```

Первая команда проверяет финансовые расчёты, импорт, изоляцию портфелей, шифрование и права на ключ, read-only доступ, обработку ошибок и атомарность синхронизации. Вторая поднимает временный сервер на свободном loopback-порту и проверяет HTTP API, CRUD, CSV, отсутствие токена в ответах и резервной копии и защиту локальных запросов. Ответы брокера в тестах подменяются: реальный токен и сетевой доступ к брокеру тестам не нужны. Все тестовые данные находятся во временных каталогах. Node нужен только для проверки синтаксиса JavaScript, для работы приложения он не требуется.
